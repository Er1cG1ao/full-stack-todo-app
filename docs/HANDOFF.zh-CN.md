# Daylight 项目交付说明

## 这次做了什么

原来的课程版 Todo CRUD 页面已升级为完整的个人任务工作台，并保留 Angular、
Maven/Spring Boot 和 H2 的技术路线。前后端仍作为一个仓库交付。

- 新界面：暖白/深绿配色、深色模式、手机侧栏、快捷键、空状态、加载提示和错误反馈。
- 任务：标题、笔记、可选截止日期、优先级、标签、子任务、重要标记、复制、批量操作。
- 整理：收件箱、今天/逾期、即将到期、已完成、项目分类、搜索筛选、排序、列表/优先级看板。
- 重复任务：每天/每周/每月；完成后自动生成下一次，避免反复勾选生成重复任务。
- 回收站：软删除、撤销、恢复，以及确认后永久删除。
- 账号：注册、真实登录、退出、修改密码、一次性恢复密钥找回密码、登录限流。
- 数据：项目改名同步更新任务，删除项目不会删除任务；JSON 导出/导入；数据库迁移与备份脚本。
- 工程：严格类型检查、自动格式检查、组件和 API 测试、GitHub Actions、本地启动器、容器部署配置。

## 怎么看成品

在项目根目录运行：

    ./scripts/dev.sh

然后打开 http://127.0.0.1:4200。注册一个自己的账号，并保存恢复密钥。
没有公开的默认账号/弱密码。数据会保存在 backend/data/，不会上传到 GitHub。

开发期间的预览使用独立数据库，不会把测试任务混进你的原始数据。
原数据库及无密码的历史账号仍保留；历史账号不能被别人通过注册认领。
交付前已经将正式本地数据库升级到新结构，并核对旧记录指纹一致。
你通过正式本地界面注册的新账号、添加的任务会保存在项目的数据目录，而不是临时测试库。

## 验证状态

前端格式检查、单元/组件测试、正式构建，以及后端 API 集成测试、数据库迁移测试
和可执行程序打包均有本地验证。具体结果见 VALIDATION.md。

浏览器本地预览访问被权限策略阻止，没有绕过，因此不把真实浏览器的视觉/端到端
验收说成已经完成。当前机器没有 Docker，容器配置也需要实际运行后再验收。

## 关于“商用级”

这次按成熟产品的体验和工程习惯完善了核心功能，但不会把它包装成已经过安全审计、
压力测试或多租户运维验证的企业服务。现在适合个人使用、作品展示和继续发展。

团队协作、附件、离线同步、邮件/推送提醒、SSO、分布式数据库/会话属于后续扩展；
这些没有暗中接入外部平台。恢复密钥丢失时也没有自动邮件找回。

导入最多每文件 500 条任务/100 个项目、5 MB，批量操作最多 100 条。
导入是追加，不覆盖，重复导入会产生副本。高保真全库恢复请使用停机数据库备份。

## 费用与安全

没有购买、付费调用、创建云服务器、开通订阅或部署收费资源。
原有课程页面的过时实现已清理，Git 历史可找回；原始数据库未删除。
备份、密码、恢复密钥和 .env 不应放进公开仓库。
